# iHelp — инструкция для рабочих сессий

Читай этот файл первым. Здесь правила работы с проектом: что можно, чего нельзя и как сдавать работу.
Отвечай пользователю по-русски. Комментарии в коде — по-русски, как в остальном проекте.

## Границы проекта

**iHelp — самостоятельный проект. Он живёт целиком в `/opt/ihelp.am` и больше нигде.**

На этом же сервере крутятся чужие проекты: сайты в `/var/www`, nginx на портах 80 и 443, процессы pm2, VPN WireGuard, записи в системном cron. **К iHelp они отношения не имеют.** Не читать их файлы, не менять конфиги, не перезапускать их процессы, не брать оттуда примеры и не переносить сюда их решения.

Если задача требует выйти за пределы `/opt/ihelp.am` — остановись и спроси владельца.

Что нужно знать об окружении:

- iHelp отвечает на порту **8080**, свои docker-контейнеры, своя база. Порты 80 и 443 на хосте держит чужой nginx: там сидят соседи и (с 22.09.2026) отдельный vhost для ihelp.am — см. следующий пункт.
- Префикс контейнеров и томов — `homecare`: это прежнее имя проекта, переименование потребовало бы переноса базы. На смысл не влияет, в командах используется как есть.
- Соседние сайты, которые smoke-тест обязан проверить после выкладки, перечислены в `NEIGHBORS` в `.env` — в репозиторий чужие домены не попадают.
- `/opt/homecare` — символическая ссылка на `/opt/ihelp.am`, осталась для старых путей.
- **Единственное исключение из границы проекта:** `/etc/nginx/sites-available/ihelp.am.conf` (+ симлинк в `sites-enabled`) — это TLS-vhost хостового nginx для `ihelp.am`/`www.ihelp.am`, проксирует на `127.0.0.1:8080`. Физически вне `/opt/ihelp.am`, но принадлежит iHelp; ничего больше в `/etc/nginx` не трогать. Правка этого файла — тот же порядок, что при его создании: бэкап `/etc/nginx`, `nginx -t` перед `reload` (не `restart`), `deploy/smoke.sh` после. Сертификат Let's Encrypt продлевает системный таймер certbot автоматически. `deploy/update.sh` этого файла не касается — он про docker-часть.

## Что это

iHelp — сервис бытовых услуг в Ереване.
Клиент выбирает услугу и параметры, видит цену, оформляет визит с выбором слота и мастера; есть подписки и пакеты визитов,
личный кабинет, кабинет мастера, админка и Control Center — доска задач проекта.

Стек: Next.js 15 (App Router, server actions), React 19, TypeScript, Tailwind 4, PostgreSQL 16 + Prisma 6, next-intl (ru/en/am), Docker Compose.
Каталог проекта: `/opt/ihelp.am` (git-репозиторий, `origin` → github.com/arturindubai/ihelp.am). Сайт: https://ihelp.am — HTTPS подключён 22.09.2026, сертификат Let's Encrypt с автопродлением (детали — «Границы проекта» выше).

## Правила, которые нельзя нарушать

1. **На сервере живут чужие проекты** — см. «Границы проекта» выше. Ничего за пределами `/opt/ihelp.am` не трогать.
2. **В прод выкладывает только деплоер** — воркер или чат, явно ведущий эту роль, и только командой `scripts/deploy-task.sh <КЛЮЧ>`: протестированный коммит, слияние, бэкап при миграции, `deploy/update.sh`, smoke, при провале откат. Рабочая сессия не мёрджит в `main` и не выкладывает — готовит ветку и сдаёт задачу в «На проверке» (`docs/DEPLOYER_GUIDE.md`). Руками `docker compose up -d --build` не вызывать никогда.
3. **`OTP_DEV_MODE` всегда `false`.** Иначе код входа виден любому посетителю.
4. **Секреты не выводить.** Ни в ответах пользователю, ни в логах, ни в коммитах. `.env` в git не попадает.
5. **Миграции базы — только вперёд.** Перед изменением схемы: `docker compose exec -T backup sh /backup.sh once`. Удаляющие миграции согласовывать с владельцем.
6. **Демо-данные и чужие сессии не трогать.** Не удалять записи в базе «чтобы почистить»: там живые настройки и задачи.
7. **Нет карточки в Control Center — нет работы.** Задачу берут командой `node scripts/cc.mjs take|next`, сдают через `review` с отчётом. Ветку без карточки деплоер не рассматривает. Если в чате просят сделать новую работу, не начинай её: положи просьбу в очередь командой `node scripts/cc.mjs intake "что нужно и зачем"` и назови ключ `IN-N`. Дальше её разберёт триаж, возьмут воркеры, выложит деплоер. Система целиком — `docs/DEV_SYSTEM.md`, роли — `docs/roles/`.
8. **Основную копию `/opt/ihelp.am` не переключать.** Каждая задача ведётся в своей рабочей копии `.claude/worktrees/<КЛЮЧ>` на ветке `task/<КЛЮЧ>`; из основной копии работает деплоер и выкладывается прод. `docker compose` без своего `COMPOSE_PROJECT_NAME` работает с продом.

## Рабочий цикл

Несколько чатов работают над iHelp параллельно, у каждого своя роль: техдиректор, разработчики, деплоер, при необходимости продакт и дизайнер. Правила общие — `docs/DEV_SYSTEM.md`; что делает каждая роль и чего не делает — `docs/roles/`; первые сообщения для чатов — `docs/roles/KICKOFF.md`. Если роль не назначена явно, ты — разработчик.

Цикл разработчика коротко (подробно — `docs/roles/DEVELOPER.md`):

1. `node scripts/cc.mjs next --agent dev` — взять следующую задачу из «В очереди» (или `take КЛЮЧ`, если задачу назвали). Команда выдаст имя `dev-N`, возьмёт аренду и создаст рабочую копию `/opt/ihelp.am/.claude/worktrees/<КЛЮЧ>` на ветке `task/<КЛЮЧ>`. Перейди в неё инструментом `EnterWorktree` с этим путём и работай только там.
2. Прочитай задачу целиком: `node scripts/cc.mjs show <КЛЮЧ>`. Непонятно зачем или непроверяемые критерии — не угадывай: вопрос в ленту и `block <КЛЮЧ> "…" --on product|owner|design|tech`.
3. Сделай изменения. Держись слоёв:
   - `src/lib` — чистые функции без доступа к серверу, покрываются тестами;
   - `src/server/services` — бизнес-логика и работа с базой;
   - `src/server/actions` — тонкие обработчики с проверкой прав (`requireSection`, `getCurrentUser`) и валидацией через zod;
   - `src/app` — страницы и маршруты; `src/components` — интерфейс.
4. Проверь в своей рабочей копии, не трогая прод:
   ```bash
   docker run --rm -v $PWD/src:/app/src -v $PWD/prisma:/app/prisma -v $PWD/messages:/app/messages \
     -w /app --entrypoint sh homecare-migrate -c 'npx prisma generate >/dev/null 2>&1; rm -rf .next; npx tsc --noEmit -p .; npx vitest run'
   ```
5. Коммиты «<КЛЮЧ>: что сделано», `git push -u origin task/<КЛЮЧ>`, затем `node scripts/cc.mjs review <КЛЮЧ> "Сделано … Проверено … Проверить … Риски …"` — задача уходит в очередь деплоера «На проверке». Мёрдж, выкладку и «Сделано» делает деплоер по `docs/DEPLOYER_GUIDE.md`.

Пока чат работает в рабочей копии задачи, хук Claude Code сам продлевает аренду (пульс). Если чат замолчит на час, сторож отметит задачу «брошенной» и через 4 часа вернёт её в очередь, ветка сохранится. Если ждёшь ответа владельца — заблокируй задачу на владельце, иначе она станет «брошенной». Не успеваешь — `handoff` с состоянием ветки.

Если ты сейчас в роли деплоера (тебя явно попросили ею быть, или задача явно про выкладку) — действуй по `docs/DEPLOYER_GUIDE.md`. Соседние сайты (чужие проекты на этом сервере) берутся из `NEIGHBORS` в `.env`: smoke-тест обязан подтвердить, что они живы после выкладки.

Если сборка упала — прод не пострадал, правь и запускай заново. Если после выкладки всё плохо: `deploy/rollback.sh` (база не откатывается).

## Соглашения кода

- **Тексты интерфейса** — только через `messages/ru.json` и переводы в админке. Зашитых строк в компонентах быть не должно: сайт работает на трёх языках.
- **Цвета и радиусы** — только токены из `src/app/theme.css` (`bg-brand`, `text-ink`, `bg-paper`…). Никаких `#hex` и `bg-white` в компонентах. Подробности — `DESIGN.md`.
- **Контакты компании** — из блока `CONTACT_*` в `.env` через `src/lib/contacts.ts`, не хардкодить.
- **Сообщения в Telegram** — через `html\`…\`` из `src/server/notify.ts`, иначе спецсимволы ломают отправку.
- **Деньги и время** — цены целыми драмами, время всегда с явным поясом Asia/Yerevan (`src/lib/time.ts`).
- **Контент** (услуги, цены, картинки, баннеры, страницы, тексты) правится в админке, а не в коде.

## Полезные команды

```bash
cd /opt/ihelp.am
docker compose ps                                   # состояние контейнеров
docker compose logs --tail 50 app                   # логи приложения
docker compose logs app | grep otp                  # код входа, пока не подключены каналы
docker compose exec -T db psql -U app -d homeservices -tAc 'select count(*) from "Order"'   # запрос к базе
node scripts/cc.mjs help                            # Control Center из командной строки: взять, сдать, передать задачу
node scripts/cc.mjs attention                       # что стоит: брошенные задачи, очередь проверки, ждут владельца
scripts/check.sh                                    # типы и тесты текущей рабочей копии
scripts/stand.sh up | down                          # лёгкий стенд ветки на 127.0.0.1:8082–8099, без настоящих токенов
systemctl stop 'ihelp-w-*' ihelp-dispatcher.timer   # немедленно остановить воркеров и диспетчер (docs/WORKERS.md)
git push -u origin task/<КЛЮЧ>                      # отправить код веткой — не main, см. «Рабочий цикл»
deploy/smoke.sh                                     # быстрая проверка, что всё живо
docker compose exec -T backup sh /backup.sh once    # бэкап прямо сейчас
```

## Код и репозиторий

Репозиторий: **github.com/arturindubai/ihelp.am**. На сервере он уже прописан как `origin` (по SSH, ключ `/root/.ssh/ihelp_deploy`).
Рабочая копия — прямо на сервере в `/opt/ihelp.am`: правки делаются там, оттуда же выкладываются и отправляются в репозиторий. Постоянного тестового стенда пока нет (DEV-3, DB-6), но для проверки конкретной ветки перед мёрджем деплоер поднимает изолированную копию по требованию на этом же сервере — `docs/DEPLOYER_GUIDE.md`.

Если `git push` отвечает `Permission denied (publickey)` — значит открытый ключ сервера ещё не добавлен в репозиторий: Settings → Deploy keys → Add deploy key, **с галкой Allow write access**, содержимое `/root/.ssh/ihelp_deploy.pub`.
