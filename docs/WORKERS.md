# Воркеры

Воркеры — автономные чаты Claude, которые сами берут работу из Control Center:

- **триаж** разбирает каждую новую карточку и раз в сутки пересматривает весь бэклог;
- **два разработчика** берут готовые код-задачи;
- **«Продукт и не-код»** исполняет задачи без кода: исследование, инструкции, тексты, настройку внешних сервисов;
- **тестировщик** проверяет сданное;
- **деплоер** выкладывает протестированное.

Воркеры работают по тем же правилам, что и обычные чаты ([DEV_SYSTEM.md](DEV_SYSTEM.md)). Разница в том, что их запускает не человек, а диспетчер, и только когда для них есть работа или человек нажал «Запустить сейчас». Токены воркеры тратят из подписки Claude (сейчас Pro), а не из API.

## Как это работает

```
таймер systemd (раз в минуту) → scripts/dispatcher.mjs
   ├─ сверяет работающих воркеров с systemd: закончившихся записывает в журнал (итог, лог, ходы, токены),
   │  нажатый «Стоп» — останавливает. Незданную задачу сразу возвращает в очередь (ветка сохраняется)
   ├─ спрашивает у Control Center план: кого запустить (src/lib/workers.ts → planDispatch)
   ├─ берёт задачу и запускает воркера отдельным юнитом systemd ihelp-w-* с ограничением по времени
   │    триаж:        пачка новых карточек → проверка готовности → в очередь / вопрос владельцу / отложить → triaged
   │                  очередь пуста и прошли сутки → обзор всего бэклога → сообщение владельцу
   │    разработчик:  «В очереди» (код) → рабочая копия → код, проверка, стенд → review → тестировщик
   │    не-код:       «В очереди» (без кода) → работа в карточке, шаги человека — вопросом владельцу → review → «Согласования»
   │    тестировщик:  «На проверке» → копия на коммите ветки → тесты, стенд, скриншоты → pass или fail
   │    деплоер:      протестированный коммит → проверка карточки и дифа → scripts/deploy-task.sh
   └─ отправляет журнал прохода во вкладку «Воркеры»
```

- **Пустые очереди — ноль токенов.** Сам диспетчер к Claude не обращается. Воркер запускается, только если есть работа, и только в пределах дневного лимита запусков своего пула.
- **Режим пула** (как в LIA):
  - «Авто» — запуск, как только в очереди есть работа;
  - «По расписанию» — не чаще раза в выбранный интервал, от 15 минут до суток;
  - «Вручную» — только кнопкой «Запустить сейчас».
- **«Запустить сейчас»** — на пуле или «▶ Запустить воркера» в шторке задачи. Диспетчер запускает воркера на ближайшем проходе, обычно в течение минуты. Кнопка работает и при выключенном общем выключателе, и в режиме «Вручную»: это явное решение человека. Не работает она только:
  - на паузе после лимита;
  - во время остановки;
  - когда подходящей работы нет.

  Если все слоты пула заняты, просьба ждёт свободного слота до 30 минут.
- **Роль задаёт задача.** Взяв задачу, воркер получает брифинг (`node scripts/cc.mjs brief КЛЮЧ`): правила своей роли, карточку, чек-лист и точные команды сдачи. В задание добавляются непрочитанные сообщения для его роли из вкладки «Сообщения».
- **Триаж** — всегда один, правила в [roles/TRIAGE.md](roles/TRIAGE.md). Его очередь:
  - новые карточки бэклога, включая входящие из Intake (`IN-N`);
  - карточки, которые человек поправил после разбора;
  - заблокированные на владельце, где человек ответил в ленте.

  За запуск триаж берёт пачку карточек (по умолчанию 6). Раз в сутки, если очередь пуста, он пересматривает весь бэклог и очередь «В очереди» и пишет итог владельцу. Код не правит. Отменять может только входящие `IN-N` после переноса в настоящие задачи.
- **Разработчики** берут только код-задачи:
  - без открытых вопросов к продукту;
  - с закрытыми зависимостями;
  - не пересекающиеся по файлам с чужой работой.

  Задачи без кода и с вопросами — для людей и обычных чатов. Во вкладке «Воркеры» у каждой задачи очереди видно, почему её не берут.
- **«Продукт и не-код»** берёт задачи без кода из «В очереди»: без открытых вопросов и с закрытыми зависимостями. Работает из основной копии только на чтение, может искать и читать страницы в интернете и проверять DNS. Результат пишет в карточку и сдаёт владельцу в «Согласования». Аккаунты, оплату, пароли и записи у регистратора не делает: блокирует задачу на владельце с пошаговой инструкцией. Правила — [roles/NOCODE.md](roles/NOCODE.md).
- **Тестировщик** ставит отметку «протестировано» на конкретный коммит ветки. Если в ветку пришёл новый коммит, нужна новая проверка.
- **Деплоер** — всегда один. Он выкладывает только протестированный коммит, по одной задаче, в окне выкладки (по умолчанию 10:00–20:00 по Еревану; «Запустить сейчас» — и вне окна). Выкладывает он только через `scripts/deploy-task.sh`. Скрипт:
  - держит замок, чтобы две выкладки не шли одновременно;
  - проверяет, что выкладывается ровно протестированный коммит;
  - сливает ветку, делает бэкап при миграции, запускает `deploy/update.sh` и перезапускает Caddy, если менялся его конфиг;
  - при провале откатывает прод и возвращает задачу с причиной;
  - при успехе закрывает задачу с коммитом и доказательством и пишет в тех-чат.
- **Стоп-условия деплоера.** Он не выкладывает, а блокирует задачу на владельце, если:
  - в «Готовности к деплою» есть ручные шаги;
  - миграция что-то удаляет;
  - в коде секреты;
  - меняются цены, оплата или права без явного решения владельца в ленте;
  - отчёт тестировщика пустой.

## Права воркеров

Права задаются в `scripts/worker-run.sh`, а поверх них действуют запреты проекта из `.claude/settings.json`.

| | Триаж | Разработчик | Продукт и не-код | Тестировщик | Деплоер |
|---|---|---|---|---|---|
| Правка файлов | нет | в своей рабочей копии | нет | нет | нет |
| Карточки | создать, дополнить, в очередь, вопрос, отменить только `IN-N` | свою задачу | свою задачу без кода | вердикт | закрыть или вернуть |
| git | чтение | коммит и пуш своей ветки; пуш в `main` запрещён | чтение | чтение | чтение |
| Интернет | нет | нет | поиск и чтение страниц | нет | нет |
| Проверки | — | `scripts/check.sh`, `scripts/stand.sh`, скриншоты | `dig`, `host` | то же, что у разработчика | `deploy/smoke.sh` |
| Прод | нет | нет | нет | нет | только `scripts/deploy-task.sh` |
| docker, systemctl, sudo, pm2, `.env`, `/var/www`, `/etc` | нет | нет | нет | нет | нет |

Время работы ограничено:

| Воркер | Минут |
|---|---|
| Триаж | 45 |
| Разработчик | 100 |
| Продукт и не-код | 60 |
| Тестировщик | 60 |
| Деплоер | 75 |

Если воркер не уложился, systemd его останавливает, а диспетчер возвращает задачу в очередь. В ленте остаётся то, что воркер успел записать.

## Подписка, а не API

- Воркер запускается как `claude -p` с токеном подписки (`CLAUDE_CODE_OAUTH_TOKEN` в `.env`). Любые API-ключи в его окружении сбрасываются.
- Токен выпускается один раз на год:
  1. На сервере выполнить `scripts/claude-login.sh`.
  2. Открыть ссылку и войти в аккаунт Claude.
  3. Вставить код.

  Проверка входа — `scripts/claude-login.sh check`. Пока токена нет, диспетчер задачи не берёт. Если вход пропал, диспетчер ставит паузу с причиной «не вошли в Claude».
- **Лимит подписки общий.** Воркеры тратят тот же лимит, что и ваши чаты с Claude. Если лимит исчерпан, диспетчер ставит всех на паузу до сброса и пишет в тех-чат. Снять паузу раньше можно кнопкой во вкладке «Воркеры». В журнале запусков видны токены и условная стоимость каждого запуска: это мера расхода лимита, деньги не списываются.
- На Pro лимиты заметно меньше, чем на Max, на котором работала LIA. Если воркеры упираются в лимит каждый день, есть четыре выхода:
  - перевести триаж в режим «По расписанию»;
  - уменьшить число одновременных воркеров;
  - снизить дневные лимиты;
  - перейти на Max.

## Управление

- **Control Center → вкладка «Воркеры»** (`/admin/control?tab=workers`):
  - **главный диспетчер:**
    - общий выключатель (по умолчанию воркеры выключены);
    - пробный режим: диспетчер пишет план в журнал, но никого не запускает;
    - «Остановить всех сейчас»;
    - «Снять паузу»;
    - окно выкладки, размер пачки триажа и частота обзора бэклога;
    - когда был последний проход диспетчера и его журнал;
  - **пулы** (триаж, разработчики, тестировщик, деплоер). У каждого:
    - «Вкл.», режим и интервал, модель, число слотов, запусков в сутки;
    - «Запустить сейчас»;
    - работающие сейчас с кнопкой «Стоп»;
    - **очередь** с причиной у каждой задачи: «следующая», «ждёт DEV-6», «пересекается с AUTH-11», «ветка не отправлена»…
  - **журнал запусков:** кто, с какой задачей или пачкой, сколько длился, чем кончился, ходы, токены, кто нажал кнопку. По клику — лог запуска.
- Остальной пульт устроен как Command Center в LIA ([CONTROL_CENTER.md](CONTROL_CENTER.md)):
  - Бэклог с дорожками и этапами;
  - Нужен ты;
  - В разработке;
  - Деплоер;
  - Планы;
  - Согласования;
  - Активность;
  - Готово;
  - Сообщения;
  - страницы Релизы, Здоровье и Логи;
  - кнопка «✦ Задача» (Intake).
- **С сервера, немедленно:**
  ```bash
  systemctl stop 'ihelp-w-*'                          # остановить работающих воркеров
  systemctl stop ihelp-dispatcher.timer               # остановить диспетчер (снова: systemctl start …)
  deploy/systemd/install.sh remove                    # убрать таймер совсем
  journalctl -u ihelp-dispatcher -n 50                # что делал диспетчер
  node scripts/dispatcher.mjs --dry-run               # кого бы запустил сейчас
  ls data/workers/                                    # задания и ответы воркеров: <id>.prompt, <id>.json, <id>.err
  ```
- **Установка таймера** — один раз: `deploy/systemd/install.sh`. Он кладёт два файла в `/etc/systemd/system` и соседние проекты не затрагивает. После обновления с таймера «раз в 5 минут» запустить его ещё раз: так подхватится «раз в минуту».

## Если что-то пошло не так

| Признак | Что это | Что делать |
|---|---|---|
| «Диспетчер опаздывает» или «не запускался» | таймер не установлен или остановлен | `deploy/systemd/install.sh`; `systemctl status ihelp-dispatcher.timer` |
| В журнале запусков «ошибка», в ленте задачи пусто | воркер упал до первой записи | «Показать лог» в журнале или `data/workers/<id>.json` и `.err`; задача уже возвращена в очередь |
| Пауза, «лимит подписки» | исчерпан лимит Claude | подождать сброса или снять паузу; при частых паузах уменьшить нагрузку |
| Пауза, «не вошли в Claude» | токен подписки истёк или отозван | `scripts/claude-login.sh`, затем «Снять паузу» |
| «Запустить сейчас» не сработало | нет подходящей работы, пауза или остановка | причина — в журнале диспетчера на вкладке «Воркеры» |
| Задача ходит по кругу «сдана → возвращена» | воркер не справляется | CTO читает ленту, уточняет требования или отдаёт задачу обычному чату |
| Триаж блокирует много карточек вопросами | в карточках не хватает решений | ответьте в ленте («Нужен ты») — триаж подхватит ответ сам |
| Выкладка вернула задачу с ошибкой | сборка или smoke упали, прод откатан | лог — путь в ленте задачи; разработчик исправляет, тестировщик проверяет заново |
