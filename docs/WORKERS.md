# Воркеры

Воркеры — это автономные чаты Claude, которые сами берут работу из Control Center: два разработчика, тестировщик и деплоер. Они работают по тем же правилам, что и обычные чаты ([DEV_SYSTEM.md](DEV_SYSTEM.md)), только запускает их не человек, а диспетчер, и только когда для них есть работа. Токены воркеры тратят из подписки Claude (сейчас Pro), а не из API.

Решения владельца от 24.09.2026, задача DEV-6:

- деплоер выкладывает сам, с защитами;
- диспетчер запускается таймером systemd на сервере;
- на старте работают два разработчика, тестировщик и деплоер, все на модели Sonnet;
- воркер запускается, только если его очередь не пуста;
- диспетчер LIA остановлен, чтобы лимит подписки шёл на iHelp.

## Как это работает

```
таймер systemd (раз в 5 минут) → scripts/dispatcher.mjs
   ├─ сверяет работающих воркеров с systemd; закончившихся записывает в журнал.
   │  Если задача осталась не сданной — сразу возвращает её в очередь (ветка сохраняется)
   ├─ спрашивает у Control Center план: кого запустить (src/lib/workers.ts → planDispatch)
   └─ берёт задачу и запускает воркера отдельным юнитом systemd ihelp-w-* с ограничением по времени
        разработчик:  «Готова к работе» → рабочая копия → код, проверка, стенд → review
        тестировщик:  «На проверке» → копия на коммите ветки → тесты, стенд, скриншоты → pass или fail
        деплоер:      протестированный коммит → проверка карточки и дифа → scripts/deploy-task.sh
```

- **Пустые очереди — ноль токенов.** Сам диспетчер к Claude не обращается. Воркер запускается, только если есть работа, и только в пределах дневного лимита запусков своего пула.
- **Роль задаёт задача.** Взяв задачу, воркер получает брифинг (`node scripts/cc.mjs brief КЛЮЧ`): правила своей роли, карточку, чек-лист и точные команды сдачи. То же самое получает и обычный чат при `take` или `next`.
- **Разработчики** берут только код-задачи без открытых вопросов к продукту, с закрытыми зависимостями и не пересекающиеся по файлам с чужой работой. Задачи без кода и с вопросами — для людей и обычных чатов.
- **Тестировщик** ставит отметку «протестировано» на конкретный коммит ветки. Если в ветку пришёл новый коммит, нужна новая проверка.
- **Деплоер** — всегда один. Он выкладывает только протестированный коммит, по одной задаче, в окне выкладки (по умолчанию 10:00–20:00 по Еревану), и только через `scripts/deploy-task.sh`. Скрипт:
  - держит замок, чтобы две выкладки не шли одновременно;
  - проверяет, что выкладывается ровно протестированный коммит;
  - сливает ветку, делает бэкап при миграции, запускает `deploy/update.sh` и перезапускает Caddy, если менялся его конфиг;
  - при провале откатывает прод и возвращает задачу с причиной;
  - при успехе закрывает задачу с коммитом и доказательством и пишет в тех-чат.
- **Стоп-условия деплоера.** Он не выкладывает, а блокирует задачу на владельце, если:
  - в «Готовности к деплою» есть ручные шаги;
  - миграция что-то удаляет;
  - в коде секреты;
  - меняются цены, оплата или права без явного решения владельца в ленте;
  - отчёт тестировщика пустой.

## Права воркеров

Права задаются в `scripts/worker-run.sh`, а поверх них действуют запреты проекта из `.claude/settings.json`.

| | Разработчик | Тестировщик | Деплоер |
|---|---|---|---|
| Правка файлов | в своей рабочей копии | нет | нет |
| git | коммит и пуш своей ветки; пуш в `main` запрещён | чтение | чтение |
| Проверки | `scripts/check.sh`, `scripts/stand.sh`, скриншоты | то же | `deploy/smoke.sh` |
| Прод | нет | нет | только `scripts/deploy-task.sh` |
| docker, systemctl, sudo, pm2, `.env`, `/var/www`, `/etc` | нет | нет | нет |

Время работы ограничено: разработчик — 100 минут, тестировщик — 60, деплоер — 75. Если воркер не уложился, systemd его останавливает, а диспетчер возвращает задачу в очередь с тем, что успело попасть в ленту.

## Подписка, а не API

- Воркер запускается как `claude -p` с токеном подписки (`CLAUDE_CODE_OAUTH_TOKEN` в `.env`). Любые API-ключи в его окружении сбрасываются.
- Токен выпускается один раз на год: на сервере выполнить `scripts/claude-login.sh`, открыть ссылку, войти в аккаунт Claude, вставить код. Проверка входа — `scripts/claude-login.sh check`. Пока токена нет, диспетчер задачи не берёт.
- **Лимит подписки общий.** Воркеры тратят тот же лимит, что и ваши чаты с Claude. Если лимит исчерпан, диспетчер ставит всех на паузу до сброса и пишет в тех-чат. Снять паузу раньше — кнопкой в Control Center → Воркеры.
- На Pro лимиты заметно меньше, чем на Max, на котором работала LIA. Если воркеры упираются в лимит каждый день, есть три выхода: уменьшить число одновременных воркеров, снизить дневные лимиты или перейти на Max.

## Управление

- **Control Center → Воркеры** (`/admin/control/workers`):
  - общий выключатель — по умолчанию воркеры выключены;
  - для каждого пула: включён ли, сколько работают одновременно, модель, запусков в сутки;
  - окно выкладки;
  - «Остановить всех сейчас» — диспетчер остановит работающих на следующем проходе, не позже чем через 5 минут;
  - «Снять паузу»;
  - журнал запусков: кто, с какой задачей, сколько длился, чем кончился, последняя строка ответа.
- **С сервера, немедленно:**
  ```bash
  systemctl stop 'ihelp-w-*'                          # остановить работающих воркеров
  systemctl stop ihelp-dispatcher.timer               # остановить диспетчер (снова: systemctl start …)
  deploy/systemd/install.sh remove                    # убрать таймер совсем
  journalctl -u ihelp-dispatcher -n 50                # что делал диспетчер
  node scripts/dispatcher.mjs --dry-run               # кого бы запустил сейчас
  ls data/workers/                                    # задания и ответы воркеров: <id>.prompt, <id>.json
  ```
- **Установка таймера** — один раз: `deploy/systemd/install.sh`. Он кладёт два файла в `/etc/systemd/system` и соседние проекты не затрагивает.

## Если что-то пошло не так

| Признак | Что это | Что делать |
|---|---|---|
| В журнале запусков «ошибка», в ленте задачи пусто | воркер упал до первой записи | ответ воркера — `data/workers/<id>.json` и `.err`; задача уже возвращена в очередь |
| «лимит подписки», воркеры на паузе | исчерпан лимит Claude | подождать сброса или снять паузу; при частых паузах уменьшить нагрузку |
| Пауза с сообщением «не вошли в Claude» | токен подписки истёк или отозван | `scripts/claude-login.sh`, затем «Снять паузу» |
| Задача ходит по кругу «сдана → возвращена» | воркер не справляется | CTO читает ленту, уточняет требования или отдаёт задачу обычному чату |
| Выкладка вернула задачу с ошибкой | сборка или smoke упали, прод откатан | лог — путь в ленте задачи; разработчик исправляет, тестировщик проверяет заново |
