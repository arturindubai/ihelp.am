# Финансовые расчёты

Сверено с кодом: 29.09.2026, ветка task/DEV-133. Правило предложено разработкой, ждёт подтверждения владельца.

## Что считается выручкой

Выручка — это сумма цен всех выполненных визитов (`Visit.status = DONE`) за период, независимо от статуса заказа.

**Входит в выручку:**
- Визит выполнен: `Visit.status = DONE`
- Дата отнесения к периоду — `Visit.finishedAt` в ереванском времени (UTC+4)
- Визиты из отменённых заказов (`Order.status = CANCELLED`) тоже входят: если услуга оказана, выручка получена

**Не входит в выручку:**
- Визиты со статусом, отличным от DONE (SCHEDULED, CONFIRMED, ON_WAY, IN_PROGRESS, CANCELLED, SKIPPED, NO_SHOW)
- **Возвраты пока не учитываются** — признака возврата по отдельному визиту в базе нет; появится вместе с регламентом (PAY-3)

**Нет онлайн-оплаты:** статус `Order.paymentStatus` (PENDING, PAID, PARTIAL, REFUNDED) в расчёт выручки не влияет. Все наличные визиты считаются фактически исполненными; онлайн-эквайринг не подключён.

## Правила

1. Период задаётся строками YYYY-MM-DD (ереванское время). Начало периода — 00:00 первого дня, конец — 24:00 последнего дня по Asia/Yerevan.
2. Выручка разбивается по типу заказа (`Order.kind`): ONE_TIME, SUBSCRIPTION, PACKAGE. Сумма трёх каналов равна общей выручке.
3. Число заказов — количество уникальных `Order.id`, у которых хотя бы один визит вошёл в выручку за период.
4. Средний чек = выручка / число заказов; если заказов нет — 0.
5. Изменение выручки к предыдущему периоду считается в процентах: `(текущая - прошлая) / прошлая × 100`. Если прошлая выручка была 0, дельта возвращается как `null` (деление на ноль).
6. График по дням — три ряда (по каналам), дни без визитов присутствуют с нулями.
7. Наличные по мастерам — визиты с `Order.paymentMethod = CASH`, сгруппированные по мастерам. Визиты без назначенного мастера (`Visit.masterId = null`) не учитываются. Возвращается два числа на мастера и два сводных показателя:
   - **«Получение не отмечено»** (`toCollect`): `Visit.cashCollected = false` — визит выполнен, мастер не нажал «Получил наличные». Статус фактического приёма неизвестен: деньги могут быть у мастера или ещё у клиента.
   - **«На руках у мастеров»** (`received`): `Visit.cashCollected = true` — мастер отметил получение, деньги у него на руках, но ещё не сданы владельцу.
   Итого по всем мастерам: `totalToCollect`, `totalReceived`, `totalAmount = totalToCollect + totalReceived`. Подсказка «Сколько мастера должны сдать» стоит у показателя `totalReceived` («На руках у мастеров»). Сколько из «получено» уже передано в кассу — не учитывается; появится вместе с регламентом наличных (PAY-3). Автоматический пересчёт `Order.paymentStatus` для наличных заказов не перезаписывает статус `REFUNDED` — его выставляет администратор вручную при возврате.
8. Рейтинг мастеров — первые 10 по выручке; визиты без мастера (`Visit.masterId = null`) не учитываются. Возвращается `ordersCount` (число уникальных заказов) и `visitsCount` нет — на уровне рейтинга считаются заказы, а не визиты.
9. Конверсия — «нет данных»: веб-аналитика (MON-3) не подключена, данных о посещениях нет.

## Крайние случаи

- **Визит в 23:59 по Еревану** (finishedAt = 2026-09-15T19:59:00Z → ереванское 23:59 15-го) попадает в день 2026-09-15.
- **Визит в 00:01 по Еревану** (finishedAt = 2026-09-15T20:01:00Z → ереванское 00:01 16-го) попадает в день 2026-09-16.
- **Пустой период** (нет выполненных визитов) → выручка 0, дельта null, все массивы с нулями.
- **Заказ отменён, но визиты выполнены** — визиты входят в выручку; если деньги возвращены клиенту, они всё равно учтутся до появления PAY-3.
- **Предыдущий период с нулевой выручкой** — дельта `null`.
- **Мастер не назначен** — визит попадает в выручку, но не в рейтинг мастеров и не в наличные.
