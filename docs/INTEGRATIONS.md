# Подключение домена, входа через Google/Apple/Telegram и почты

Код для всего этого уже написан и выкачен. Ниже — что сделать вам и что после этого делаю я.

## Шаг 1. Домен — готово (задача INFRA-1…3)

Сделано 22.09.2026: домен `ihelp.am` подключён, сертификат Let's Encrypt с автопродлением, `COOKIE_SECURE=true`. Сайт открывается по **https://ihelp.am**. Дальше во всех шагах используется этот адрес — все адреса возврата (redirect URI) для Google/Apple/Telegram теперь настоящие, не заготовки на будущее.

## Шаг 2. Вход через Google (задача AUTH-8) — готово

Подключено 28.09.2026. Кнопка «Войти через Google» есть на странице входа, вход проверен: `hello@ihelp.am` → админка, запись `auth.google` в журнале действий.

Где что настроено:

- **Google Cloud:** проект `iHelp` (ID `ihelp-510007`) под аккаунтом `hello@ihelp.am` (Google Workspace iHelp, шаг 6), без организации. Google Auth Platform → Clients → OAuth-клиент **«ihelp.am web»**, тип Web application, адрес возврата `https://ihelp.am/api/auth/google/callback`.
- **Экран согласия (Branding/Audience):** приложение «iHelp», тип **External**, статус **In production** — входить может любой аккаунт Google, не только тестовые. Ссылки: сайт `https://ihelp.am`, политика `https://ihelp.am/ru/p/privacy`, условия `https://ihelp.am/ru/p/offer`, домен `ihelp.am`, почта поддержки и разработчика — `hello@ihelp.am`. Запрашиваются только `openid email profile`, поэтому проверка приложения Google не нужна. **Логотип не загружен намеренно:** с логотипом Google требует проверку бренда, и до её окончания экран согласия показывает предупреждение.
- **Сайт:** Админка → Настройки → Вход через Google — Client ID, Client Secret (в базе зашифрован, `Setting.google`), переключатель включён. Выкладка и сид эту настройку не трогают. Если секрет потеряется, его не восстановить: в Google Cloud → Clients → «ihelp.am web» → **Add secret**, новый вставить в настройки, старый отключить.
- **Профиль владельца:** в основную учётную запись владельца (та, в которую пускает ссылка `ADMIN_LOGIN_TOKEN`) вписан `hello@ihelp.am` как подтверждённый email.

Как это работает:

- Пускаем только тех, у кого **этот же email уже указан в профиле** пользователя. Незнакомый аккаунт Google не создаёт нового пользователя и не получает доступ: «Этот Google-аккаунт не привязан».
- Значит, сотрудник или клиент сначала входит другим способом (Telegram-бот, код на почту) и указывает эту почту в профиле — или администратор вписывает её сам.
- Каждый вход пишется в журнал действий, попытка с непривязанной почтой уходит в тех-алерты.
- Регистрация нового клиента через Google сейчас невозможна: у пользователя обязателен телефон. Это отдельная задача — IN-29 (там же — пускать только по подтверждённой почте).

## Шаг 3. Почта через Resend (задача NOTIFY-8)

Нужно от вас:

1. Зарегистрируйтесь на [resend.com](https://resend.com) (есть бесплатный тариф).
2. **Domains → Add Domain**: укажите ваш домен. Resend выдаст DNS-записи (SPF, DKIM, иногда DMARC) — добавьте их у регистратора или пришлите мне.
3. Дождитесь статуса «Verified».
4. **API Keys → Create API Key** с правом отправки писем, скопируйте ключ (он показывается один раз).

Дальше вы или я: Админка → Настройки → **Почта (Resend)** → вставить ключ, указать отправителя вида `iHelp <info@ваш-домен>`, включить переключатель, сохранить. Там же кнопка **«Отправить тестовое письмо»** — проверяет всё сразу.

**Коды входа по email (AUTH-14).** Через эту же почту уходят коды входа: на странице входа появляется способ «По email». Пускает только по подтверждённому адресу (`User.emailVerifiedAt`) — адрес подтверждается кодом из письма при регистрации или в профиле. Ответ на запрос кода одинаков для любого адреса, письмо уходит только настоящему подтверждённому аккаунту. Лимиты те же, что у кодов на телефон (5 в час и 10 в сутки на адрес, 20 в час с одного IP — см. INFRA-6 про реальный IP). Бесплатный тариф Resend — 3000 писем в месяц и не больше 100 в день.

Домен ihelp.am обслуживает Cloudflare (DNS в вашем аккаунте Cloudflare): записи, которые выдал Resend (DKIM `resend._domainkey`, SPF и MX на поддомене отправки), добавляются там. На корневом домене почты нет, MX Resend его не затрагивает.

Дальше письма можно включать в сценарии: подтверждение заказа, напоминания, чеки (задачи NOTIFY-3, NOTIFY-4, NOTIFY-7).

## Шаг 4. Вход через Apple (задача AUTH-9)

Код готов 23.09.2026: маршруты входа, проверка состояния перехода, привязка по email — устроено так же, как у Google. Требует членства в **Apple Developer Program** (платное, около $99/год). По словам владельца, аккаунт мог быть оформлен ранее на `iamegoiste@gmail.com` — первым делом стоит проверить в [developer.apple.com/account](https://developer.apple.com/account), есть ли уже активная подписка, прежде чем оформлять новую.

Нужно от вас:

1. В Apple Developer: **Certificates, Identifiers & Profiles → Identifiers → App IDs** — если под iHelp ещё нет идентификатора, создайте (или используйте существующий).
2. Там же **Identifiers → Services IDs → +** — создайте Services ID вида `am.ihelp.web` (это и есть `Client ID` для входа на сайте). В настройках Services ID включите **Sign in with Apple**, configure: Domain `ihelp.am`, Return URL `https://ihelp.am/api/auth/apple/callback`.
3. **Keys → +** — создайте ключ с включённым Sign in with Apple, привяжите к App ID из шага 1. Скачайте файл `.p8` **один раз** (повторно скачать нельзя) и запомните его **Key ID**.
4. Запишите свой **Team ID** (виден в правом верхнем углу консоли, под именем аккаунта).

Дальше вы или я: Админка → Настройки → **Вход через Apple** → вставить Team ID, Key ID, Services ID (Client ID) и целиком содержимое файла `.p8`, включить переключатель, сохранить. На странице входа появится кнопка «Войти через Apple».

Работает по той же логике, что и Google: пускает только тех, у кого этот email уже указан в профиле пользователя — новый аккаунт не создаётся, попытка с непривязанной почтой уходит в тех-алерты, каждый вход — в журнал действий, приватный ключ хранится в базе зашифрованным.

## Шаг 5. Вход через Telegram (задача AUTH-10)

Два разных способа, для сайта нужен один из них — решите, какой:

- **Виджет на сайте** — кнопка «Войти через Telegram» прямо на странице входа, требует привязать домен к боту: в @BotFather → `/setdomain` → `ihelp.am`.
- **Вход через бота** — сотрудник открывает бота команды и одной кнопкой делится номером телефона, бот присылает одноразовую ссылку входа. Не требует домена и виджета, ложится на уже существующий номер как идентификатор.

Для обоих нужен бот в @BotFather (тот же, что и для уведомлений команде — задача NOTIFY-1, если он уже создан, можно использовать его). Токен вписывается в Админка → Настройки → Уведомления.

**Как работает вход через бота сейчас (AUTH-10, AUTH-11, AUTH-13).** Бот принимает номер **только из собственного контакта отправителя**: Telegram присылает в `contact.user_id` владельца номера, и он должен совпасть с `from.id` (чужой, пересланный или вписанный вручную контакт — отказ, иначе номер владельца с сайта давал бы вход в его аккаунт). Дальше:

- номер уже есть в iHelp — бот присылает одноразовую ссылку входа (10 минут);
- номера нет — бот присылает ссылку `/ru/login?complete=…` на завершение регистрации: номер подтверждён Telegram, на сайте вводятся имя и email, email подтверждается кодом из письма (нужна подключённая почта, AUTH-14), и только потом создаётся аккаунт.

Кнопка «Войти через Telegram» появляется на странице входа и в форме оформления заказа, когда вебхук бота подключён: имя бота сохраняется в настройках (`notify.telegramBotUsername`) при регистрации вебхука. Подключить: Админка → Настройки → Уведомления → «Подключить вход через Telegram-бота» (или `scripts/connect-telegram-bot.mts`). Отключить — снять вебхук (`deleteWebhook`) и очистить имя бота в настройках.

## Что остаётся на телефоне

Вход по номеру телефона никуда не девается, когда подключён SMS (OTP-2, отложен до 10.10.2026). До тех пор клиенты входят и регистрируются через Telegram-бота (номер) и коды из писем (email). Google и Apple — удобство для сотрудников и части клиентов: они привязывают только уже существующий аккаунт по email — нового клиента через них не завести (регистрация через них — после подключения SMS). Заказ всё равно требует телефон, иначе мастер не сможет приехать и позвонить.

**Статус AUTH-1 (25.09.2026).** Задача выполнена: два реальных канала доставки кодов подключены и работают — Telegram-бот (AUTH-13) и email через Resend (AUTH-14). Регистрация нового клиента работает: номер подтверждает Telegram-бот, email — кодом из письма (AUTH-11). Новый клиент может зарегистрироваться самостоятельно. SMS (OTP-2) — по плану после 10.10.2026; Telegram Gateway (OTP-3) — отдельная задача позже.

## Шаг 6. Почта на домене — hello@ihelp.am (задача INFRA-4) — готово

Деловой ящик для переписки с клиентами и партнёрами. С Resend (шаг 3) он не связан: Resend отправляет письма из кода (коды входа, чеки) с `no-reply@ihelp.am`, а hello@ihelp.am — обычный почтовый ящик, куда люди пишут вам и откуда вы отвечаете.

**Сервис: Google Workspace**, отдельная организация «iHelp» (не Globrex). Владелец завёл её сам 28.09.2026; изначально выбирали Zoho Mail (25.09), но у владельца уже есть опыт с Workspace, и один аккаунт закрывает и почту, и Google Cloud для входа через Google (шаг 2).

- Ящик и администратор организации — `hello@ihelp.am`. Админ-консоль: [admin.google.com](https://admin.google.com) под этим аккаунтом.
- **Пробный период до 12.10.2026.** Дальше Workspace платный (около 7–8 $ в месяц за ящик): к этой дате в Admin → Billing должен быть способ оплаты, иначе почта и вход в Google Cloud остановятся.
- Письма читаются в обычном Gmail (веб и приложение на телефоне) — IMAP и пароли приложений не нужны: добавьте аккаунт `hello@ihelp.am` в приложение Gmail.
- Второй человек (партнёр, оператор): новый пользователь в Admin → Users — это ещё одна платная лицензия; бесплатный вариант — группа Google `hello@` с участниками (Admin → Groups), тогда письма получают все участники.

### DNS-записи в Cloudflare (корень ihelp.am)

| Тип | Имя | Значение | Для чего |
|-----|-----|----------|----------|
| MX | `@` | `aspmx.l.google.com` (1), `alt1`/`alt2.aspmx.l.google.com` (5), `alt3`/`alt4.aspmx.l.google.com` (10) | входящая почта |
| TXT | `@` | `v=spf1 include:_spf.google.com ~all` | SPF |
| TXT | `google._domainkey` | ключ из Admin → Apps → Gmail → Authenticate email | DKIM, статус «Authenticating email with DKIM» |
| TXT | `@` | `google-site-verification=…` | подтверждение домена в Google |
| TXT | `_dmarc` | `v=DMARC1; p=none;` | DMARC в режиме наблюдения |

Записи Resend живут на поддомене отправки и на `resend._domainkey` — с записями Google не пересекаются. Включать `include:` Resend в SPF корня не нужно: Resend отправляет с собственным адресом возврата на поддомене, а DMARC проходит по его DKIM-подписи.

**Не трогать при работе с DNS:** MX и SPF на корне — это почта hello@. Удаление или замена этих записей молча остановит приём писем. Выкладка сайта (`scripts/deploy-task.sh`, `deploy/update.sh`) в DNS не ходит.

### Проверка

1. `dig +short MX ihelp.am` — пять серверов `*.aspmx.l.google.com`.
2. Письмо с любого внешнего адреса на `hello@ihelp.am` приходит во «Входящие» Gmail этого аккаунта.
3. Ответ с `hello@ihelp.am` на Gmail показывает в «Показать оригинал» `SPF: PASS`, `DKIM: PASS`, `DMARC: PASS`.

Когда письма стабильно доходят, DMARC можно ужесточить до `p=quarantine`.
