# Подключение домена, входа через Google/Apple/Telegram и почты

Код для всего этого уже написан и выкачен. Ниже — что сделать вам и что после этого делаю я.

## Шаг 1. Домен — готово (задача INFRA-1…3)

Сделано 22.09.2026: домен `ihelp.am` подключён, сертификат Let's Encrypt с автопродлением, `COOKIE_SECURE=true`. Сайт открывается по **https://ihelp.am**. Дальше во всех шагах используется этот адрес — все адреса возврата (redirect URI) для Google/Apple/Telegram теперь настоящие, не заготовки на будущее.

## Шаг 2. Вход через Google (задача AUTH-8)

Нужно от вас (10 минут):

1. Откройте [Google Cloud Console](https://console.cloud.google.com/) под рабочим аккаунтом, создайте проект (например, `iHelp`).
2. **APIs & Services → OAuth consent screen**: тип «External», название приложения, почта поддержки, домен сайта. Пока пользователей мало, режим «Testing» подойдёт, но тогда в «Test users» добавьте почты сотрудников.
3. **APIs & Services → Credentials → Create credentials → OAuth client ID**, тип «Web application».
4. В поле **Authorized redirect URIs** вставьте адрес, который показан в Админка → Настройки → Вход через Google: `https://ihelp.am/api/auth/google/callback`.
5. Скопируйте **Client ID** и **Client Secret**.

Дальше вы или я: Админка → Настройки → **Вход через Google** → вставить оба значения, включить переключатель, сохранить. На странице входа появится кнопка «Войти через Google».

Как это работает и почему безопасно:

- Пускаем только тех, у кого **этот же email уже указан в профиле** пользователя. Незнакомый аккаунт Google не создаст нового пользователя и не получит доступ.
- Значит, до первого входа через Google сотрудник должен один раз войти по номеру телефона и указать рабочую почту в профиле (или вы впишете её ему).
- Каждый вход пишется в журнал действий, попытка входа с непривязанной почтой — в тех-алерты.
- Секрет клиента хранится в базе в зашифрованном виде.

Ваш случай: чтобы вы могли входить через Google, откройте профиль на сайте (`/ru/account`) и укажите в нём вашу рабочую почту. После этого кнопка «Войти через Google» будет пускать вас без кода и без ссылки с токеном.

## Шаг 3. Почта через Resend (задача NOTIFY-8)

Нужно от вас:

1. Зарегистрируйтесь на [resend.com](https://resend.com) (есть бесплатный тариф).
2. **Domains → Add Domain**: укажите ваш домен. Resend выдаст DNS-записи (SPF, DKIM, иногда DMARC) — добавьте их у регистратора или пришлите мне.
3. Дождитесь статуса «Verified».
4. **API Keys → Create API Key** с правом отправки писем, скопируйте ключ (он показывается один раз).

Дальше вы или я: Админка → Настройки → **Почта (Resend)** → вставить ключ, указать отправителя вида `iHelp <info@ваш-домен>`, включить переключатель, сохранить. Там же кнопка **«Отправить тестовое письмо»** — проверяет всё сразу.

**Коды входа по email (AUTH-14).** Через эту же почту уходят коды входа: на странице входа появляется способ «По email». Пускает только по подтверждённому адресу (`User.emailVerifiedAt`) — адрес подтверждается кодом из письма при регистрации или в профиле. Ответ на запрос кода одинаков для любого адреса, письмо уходит только настоящему подтверждённому аккаунту. Лимиты те же, что у кодов на телефон (5 в час и 10 в сутки на адрес, 20 в час с одного IP — см. INFRA-6 про реальный IP). Бесплатный тариф Resend — 3000 писем в месяц и не больше 100 в день.

Домен ihelp.am обслуживает Cloudflare (DNS в вашем аккаунте Cloudflare): записи, которые выдал Resend (DKIM `resend._domainkey`, SPF и MX на поддомене отправки), добавляются там. На корневом домене почты нет, MX Resend его не затрагивает.

Дальше письма можно включать в сценарии: подтверждение заказа, напоминания, чеки (задачи NOTIFY-3, NOTIFY-4, NOTIFY-7).

## Шаг 4. Вход через Apple (задача AUTH-9)

Код готов 23.09.2026: маршруты входа, проверка состояния перехода, привязка по email — устроено так же, как у Google. Требует членства в **Apple Developer Program** (платное, около $99/год). По словам владельца, аккаунт мог быть оформлен ранее на `iamegoiste@gmail.com` — первым делом стоит проверить в [developer.apple.com/account](https://developer.apple.com/account), есть ли уже активная подписка, прежде чем оформлять новую.

Нужно от вас:

1. В Apple Developer: **Certificates, Identifiers & Profiles → Identifiers → App IDs** — если под iHelp ещё нет идентификатора, создайте (или используйте существующий).
2. Там же **Identifiers → Services IDs → +** — создайте Services ID вида `am.ihelp.web` (это и есть `Client ID` для входа на сайте). В настройках Services ID включите **Sign in with Apple**, configure: Domain `ihelp.am`, Return URL `https://ihelp.am/api/auth/apple/callback`.
3. **Keys → +** — создайте ключ с включённым Sign in with Apple, привяжите к App ID из шага 1. Скачайте файл `.p8` **один раз** (повторно скачать нельзя) и запомните его **Key ID**.
4. Запишите свой **Team ID** (виден в правом верхнем углу консоли, под именем аккаунта).

Дальше вы или я: Админка → Настройки → **Вход через Apple** → вставить Team ID, Key ID, Services ID (Client ID) и целиком содержимое файла `.p8`, включить переключатель, сохранить. На странице входа появится кнопка «Войти через Apple».

Работает по той же логике, что и Google: пускает только тех, у кого этот email уже указан в профиле пользователя — новый аккаунт не создаётся, попытка с непривязанной почтой уходит в тех-алерты, каждый вход — в журнал действий, приватный ключ хранится в базе зашифрованным.

## Шаг 5. Вход через Telegram (задача AUTH-10)

Два разных способа, для сайта нужен один из них — решите, какой:

- **Виджет на сайте** — кнопка «Войти через Telegram» прямо на странице входа, требует привязать домен к боту: в @BotFather → `/setdomain` → `ihelp.am`.
- **Вход через бота** — сотрудник открывает бота команды и одной кнопкой делится номером телефона, бот присылает одноразовую ссылку входа. Не требует домена и виджета, ложится на уже существующий номер как идентификатор.

Для обоих нужен бот в @BotFather (тот же, что и для уведомлений команде — задача NOTIFY-1, если он уже создан, можно использовать его). Токен вписывается в Админка → Настройки → Уведомления.

**Как работает вход через бота сейчас (AUTH-10, AUTH-11, AUTH-13).** Бот принимает номер **только из собственного контакта отправителя**: Telegram присылает в `contact.user_id` владельца номера, и он должен совпасть с `from.id` (чужой, пересланный или вписанный вручную контакт — отказ, иначе номер владельца с сайта давал бы вход в его аккаунт). Дальше:

- номер уже есть в iHelp — бот присылает одноразовую ссылку входа (10 минут);
- номера нет — бот присылает ссылку `/ru/login?complete=…` на завершение регистрации: номер подтверждён Telegram, на сайте вводятся имя и email, email подтверждается кодом из письма (нужна подключённая почта, AUTH-14), и только потом создаётся аккаунт.

Кнопка «Войти через Telegram» появляется на странице входа и в форме оформления заказа, когда вебхук бота подключён: имя бота сохраняется в настройках (`notify.telegramBotUsername`) при регистрации вебхука. Подключить: Админка → Настройки → Уведомления → «Подключить вход через Telegram-бота» (или `scripts/connect-telegram-bot.mts`). Отключить — снять вебхук (`deleteWebhook`) и очистить имя бота в настройках.

## Что остаётся на телефоне

Вход по номеру телефона никуда не девается, когда подключён SMS (OTP-2, отложен до 10.10.2026). До тех пор клиенты входят и регистрируются через Telegram-бота (номер) и коды из писем (email). Google и Apple — удобство для сотрудников и части клиентов: они привязывают только уже существующий аккаунт по email — нового клиента через них не завести (регистрация через них — после подключения SMS). Заказ всё равно требует телефон, иначе мастер не сможет приехать и позвонить. Пока WhatsApp (OTP-1) отложен по решению владельца, задача **AUTH-1** (канал доставки кодов клиентам — SMS или Telegram Gateway) остаётся блокером запуска для новых клиентов.

## Шаг 6. Почта на домене — hello@ihelp.am (задача INFRA-4)

Это деловой ящик для переписки с клиентами и партнёрами. Он не связан с Resend (шаг 3): Resend — это транзакционные письма из кода (коды входа, чеки), а Zoho Mail — обычный почтовый ящик, куда люди пишут вам и вы пишете им.

**Сервис: [Zoho Mail](https://mail.zoho.com)** — бесплатный тариф до 5 пользователей, 5 ГБ каждому, свой домен, IMAP/SMTP, без рекламы.

### Действия владельца

#### A. Создать аккаунт Zoho Mail

1. Откройте **https://mail.zoho.com**, нажмите **Sign Up for Free**.
2. Выберите **Zoho Mail Lite** (первая колонка, бесплатно). Зарегистрируйтесь.
3. На вопрос «Do you own a domain?» — выберите **Yes, I already have a domain**, введите `ihelp.am`.

#### B. Добавить и подтвердить домен

1. Zoho покажет DNS-запись для подтверждения (TXT-запись вида `zoho-verification=zmXXXXXX`).
2. Откройте **Cloudflare** → свой аккаунт → домен `ihelp.am` → **DNS → Records → Add record**:
   - **Type:** TXT
   - **Name:** `@` (или `ihelp.am`)
   - **Content:** значение `zoho-verification=zmXXXXXX` из панели Zoho
   - **TTL:** Auto
   - **Proxy:** выключен (серый облачок)
3. Вернитесь в Zoho и нажмите **Verify**. Может занять до 15 минут.

#### C. Добавить DNS-записи для почты

После подтверждения домена Zoho выдаст все нужные записи. Добавьте каждую в Cloudflare → DNS:

**MX-записи** (входящая почта):

| Type | Name | Mail server | Priority | TTL | Proxy |
|------|------|-------------|----------|-----|-------|
| MX | `@` | `mx.zoho.com` | 10 | Auto | выкл. |
| MX | `@` | `mx2.zoho.com` | 20 | Auto | выкл. |
| MX | `@` | `mx3.zoho.com` | 50 | Auto | выкл. |

**SPF** (авторизация отправителя):

| Type | Name | Content | TTL | Proxy |
|------|------|---------|-----|-------|
| TXT | `@` | `v=spf1 include:zoho.com ~all` | Auto | выкл. |

> Если у вас уже есть SPF-запись для Resend, объедините их в одну:
> `v=spf1 include:zoho.com include:resend.com ~all`

**DKIM** (цифровая подпись писем):

Значение генерируется Zoho индивидуально для вашего домена — скопируйте его из панели Zoho Mail:

1. В Zoho Mail → **Admin Panel** → **Domains** → `ihelp.am` → **Email Authentication** → **DKIM** → **Configure**.
2. Нажмите **Generate New DKIM Key**, скопируйте TXT-запись.
3. В Cloudflare добавьте:
   - **Type:** TXT
   - **Name:** `zoho._domainkey` (именно так, без `ihelp.am`)
   - **Content:** вставить значение из Zoho (начинается с `v=DKIM1; k=rsa; p=...`)
   - **TTL:** Auto, Proxy: выкл.
4. Вернитесь в Zoho и нажмите **Verify**.

**DMARC** (политика для спам-фильтров):

| Type | Name | Content | TTL | Proxy |
|------|------|---------|-----|-------|
| TXT | `_dmarc` | `v=DMARC1; p=none; rua=mailto:hello@ihelp.am; sp=none; aspf=r;` | Auto | выкл. |

> `p=none` — наблюдение без блокировки. Когда убедитесь, что письма доходят, смените на `p=quarantine`.

#### D. Создать ящик hello@ihelp.am

1. В Zoho Mail → **Admin Panel** → **User Details** → **Add User**.
2. Заполните: First Name `iHelp`, Last Name `Team` (или как удобно), Email `hello`.
3. Задайте пароль, сохраните. Ящик `hello@ihelp.am` создан.

### Проверка перед подключением на устройства

1. Зайдите в Zoho Mail по адресу **mail.zoho.com** под ящиком `hello@ihelp.am`.
2. Отправьте тестовое письмо на любой внешний адрес (Gmail, Yandex).
3. Убедитесь, что ответное письмо пришло в папку «Входящие».
4. Проверьте заголовки полученного письма — должны быть `DKIM=pass` и `SPF=pass`.

Дополнительно можно проверить настройки через сервис **[MXToolbox](https://mxtoolbox.com)**: введите `ihelp.am` в поле Email Health.

### Подключение на устройства

Используйте **IMAP** (не POP3) — письма будут синхронизированы на всех устройствах.

**Параметры для всех устройств:**

| Параметр | Значение |
|----------|----------|
| Входящая почта (IMAP) | `imap.zoho.com`, порт `993`, SSL/TLS |
| Исходящая почта (SMTP) | `smtp.zoho.com`, порт `465`, SSL/TLS |
| Имя пользователя | `hello@ihelp.am` |
| Пароль | пароль от ящика в Zoho |

> Если в Zoho включена двухфакторная аутентификация — создайте App Password: **My Account → Security → App Passwords → Add** и используйте его вместо основного пароля.
