# Разработка LIA → что берём в iHelp

Исследование 25.09.2026, только чтение. Полная версия для владельца: https://claude.ai/artifact/L2jP2VY8ZKfDPhHQHQiQdv.

Источники в LIA (`/var/www/ai-blog-app`, читать можно, править нельзя, `server/.env` не читать):
- `CLAUDE.md` — правила;
- `docs/DEV-SYSTEM.md` — регламент с 02.07.2026;
- `docs/command-center/`:
  - `preamble.md` — общая инструкция воркера;
  - `deployer.md`, `supervisor.md`;
  - `worker-*.md` — навыки шести ролей;
- `scripts/`: `lia-cc-dispatcher.mjs` (диспетчер пулов), `lia-tg-poll.mjs` (Telegram), `lia-intake.mjs`, `lia-auto-approver.mjs`;
- `client/src/app/screens/admin/`: экран `zones/CommandCenter.tsx`, окно `IntakeChat.tsx`, стили `adminRedesign.css`;
- база `data/storage.db`, таблицы `lia_tasks`, `worker_pool`, `worker_runs`, `lia_intake_log` — только `sqlite3 -readonly`.

## Главное

1. **В LIA сейчас действует Command Center v2 (июль 2026).** Состав:
   - одна доска `lia_tasks`;
   - шесть дорожек: Integrator, Product, Designer, KB, Bugs, QA;
   - пулы воркеров «роль × модель»: Sonnet для S/M, Opus для L/XL;
   - один деплоер-интегратор;
   - «Done» только с доказательством.

   Конвейер на `lia.mjs` выключили 05.06.2026 как избыточный для двух человек. Его идеи — один исполнитель, один деплоер, сторож — остались в v2.
2. **Главный урок LIA — правда доски.** Разовый импорт из Notion и массовый «Approve» дали 693 «Done» из 714 без коммита. В iHelp гейты стоят в коде с DEV-13, их не ослаблять.
3. **В LIA воркер сдаёт дифф вложением, интегратор применяет его.** В iHelp работа идёт иначе:
   - воркер ведёт свою ветку;
   - тестировщик проверяет конкретный коммит;
   - деплоер выкладывает через `scripts/deploy-task.sh`.

   Наша схема надёжнее, оставляем её.
4. **Intake в LIA разбирает текст через API за секунды.** iHelp работает на подписке: разбирает воркер триажа за минуты. Нужен быстрый слот для входящих.
5. **Задачи из Telegram LIA принимает отдельный внутренний бот** (`getUpdates`, «баг:/фича:/идея:», «статус»). Для iHelp — отдельный бот команды, не бот входа клиентов.

## Решения

| Что в LIA | Решение | Как в iHelp |
|---|---|---|
| Один трекер | берём | Control Center |
| Статусы Inbox → Todo → Doing → Done + Blocked | берём | Бэклог → В очереди → В работе → На проверке → Сделано + Заблокирована, Отменена (DEV-18) |
| Доказательство для «Done», статус эпика из детей | берём | гейты DEV-13 |
| Архив вместо удаления | адаптируем | отмена с причиной вместо удаления карточки (DEV-23); в Библиотеке — архив записей (DEV-20) |
| Дорожки по исполнителю | берём | Входящие, Разработка, Ошибки и аудит, Инфраструктура, Дизайн, Продукт и контент |
| Пулы, режимы авто/вручную/по расписанию, «Run now» | берём | DEV-17; модель Opus для задач L — DEV-26, когда позволит подписка |
| Сторож по пульсу | берём | аренда 60 мин, пульс хука, возврат через 4 ч |
| Результат — дифф вложением | не нужно | ветка + тест коммита |
| Единственный деплоер с допуском | берём | `deploy-task.sh`: замок, проверка папки, протестированный коммит, откат |
| Гейты деплоера PRD/дизайн/KB/QA | адаптируем | тестировщик есть; гейт макета для экранов — DEV-24 |
| `release_note`, `ceo_summary` | берём | строка «что изменилось для людей» и резюме для владельца с «Принять/Вернуть» в шторке — DEV-22 |
| Мгновенный Intake через API | адаптируем | быстрый слот триажа для входящих `IN-N` (DEV-20); дубли ищет триаж |
| Отдельный Telegram-бот для задач | берём | бот команды (DEV-20): владелец создаёт бота в @BotFather, токен — в «Ключи» |
| Secrets: ключи в админке | берём | «Ключи» (DEV-20): значение только на запись, в базе зашифровано |
| Лог-вотчер заводит карточки из ошибок | адаптируем | ошибки прод-логов → входящие с отпечатком — DEV-25 |
| Три постоянных dev-стенда | не нужно | стенд по требованию `scripts/stand.sh` |
| Canon Library в базе | берём | «Библиотека» (DEV-20): документы репозитория снимаются при каждой выкладке, записи команды — с версиями |
| Супервизор-чаты по ролям | не нужно | пока мала команда |
| INTAKE-протокол с «GO» | не нужно | очередь и триаж; пересказ «что я понял» — в карточке от триажа |
| Тёмный плотный пульт, резюме в шторке с «Принять/Вернуть» | адаптируем | цвета и тёмную тему не переносим — решение владельца 25.09.2026; резюме в шторке — DEV-22 |
| Пакт честности, список «никогда не делаем» | берём | в `CLAUDE.md`, воркеры не заводят задачи — DEV-21 |
| Не выкладывать в пятницу вечером | адаптируем | окно 10–20; будни — на решение владельца |

## Грабли LIA — не повторять

- Два трекера без синхронизации.
- «Done» без доказательства: массовое одобрение и импорт статусов.
- Ручное удаление карточек.
- Устаревшие разделы в `CLAUDE.md`, которые агенты принимают за правила.
- JSON отчётов, собранный вручную в `curl`: ошибки разбора на сервере. У нас работа идёт через `cc.mjs`.
- Разный регистр категорий ломал захват задач. У нас роли и пулы — константы в одном файле с тестами.
- Система тяжелее команды.
- Молчаливые падения воркеров. У нас в журнале запуска есть лог и причина.

## План переноса

1. DEV-18: статусы, «Продукт и не-код», права тестировщика, «разбирает сейчас» в Intake — на проверке.
2. DEV-20: быстрый слот триажа для входящих, бот команды в Telegram, «Ключи» и «Библиотека» — на проверке, включает DEV-18.
3. DEV-21: `CLAUDE.md` — пакт честности, список «никогда», запрет воркерам заводить задачи.
4. DEV-22: строка «что изменилось для людей» и резюме для владельца с «Принять/Вернуть». Цвета пульта не меняем — решение владельца.
5. DEV-23: архив вместо удаления карточек.
6. DEV-24: гейт макета для экранов.
7. DEV-25: лог-вотчер → входящие.
8. DEV-26: модель Opus для крупных задач — после решения владельца о подписке.

Задачи 3–8 зависят от DEV-20: воркеры возьмут их после его выкладки.
