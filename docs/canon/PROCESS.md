# Канон: алгоритм работы над задачами

Это свод правил, по которым живёт доска Control Center и воркеры. Подробности по каждой роли — в `docs/roles/`, по системе в целом — `docs/DEV_SYSTEM.md`, по воркерам — `docs/WORKERS.md`. Если этот файл и код расходятся — правда в коде (`src/lib/cc-flow.ts`, `src/lib/workers.ts`), а этот файл надо поправить задачей.

## 1. Статусы и кто их ставит

| Статус | Что значит | Кто переводит сюда | Куда отсюда |
|---|---|---|---|
| **Бэклог** | карточка есть, но ещё не разобрана или отложена | Intake, триаж, владелец, техдиректор | В очереди (триаж), Заблокирована (вопрос), Отменена |
| **В очереди** | разобрана, критерии проверяемы, зависимости закрыты — можно брать | триаж, владелец, техдиректор, продакт; возврат с проверки; разблокировка | В работе (аренда), Бэклог, Заблокирована |
| **В работе** | кто-то держит аренду и работает в своей копии `task/<КЛЮЧ>` | только аренда (`take`/`next`) | На проверке (`review`), В очереди (`handoff`), Заблокирована |
| **На проверке** | ветка отправлена, отчёт написан; сначала тестировщик, потом деплоер; не-код — владелец в «Согласованиях» | разработчик, воркер «Продукт и не-код», техдиректор | Сделано (деплоер/владелец), В очереди (возврат), Заблокирована |
| **Заблокирована** | нужен человек или внешнее событие: `blockedOn` = owner, product, design, tech, external, deps | любой, с причиной | туда, откуда заблокирована (см. §3), Бэклог, Отменена |
| **Сделано** | код выложен в прод с коммитом, не-код принят владельцем | деплоер, владелец | В очереди (переоткрыть) |
| **Отменена** | не делаем; карточка и лента остаются | владелец, техдиректор, продакт; триаж — только `IN-N` | Бэклог |

Удаления карточек нет. «Сделано» без доказательства не бывает: код — коммит в `main` и что проверено после выкладки; не-код — отчёт или файл.

## 2. Откуда берутся очереди

- **Триаж**: карточки бэклога без разбора (`triagedAt` пуст), входящие `IN-N`, карточки, которые человек поправил после разбора, и заблокированные на владельце или продукте, где человек ответил в ленте после блокировки. `IN-N` берётся сразу, отдельным слотом. Раз в сутки при пустой очереди — обзор всего бэклога.
- **Продакт**: заблокированные «на продукте» (`blockedOn = product`) — отвечает, дописывает требования, снимает блокировку; раз в сутки обзор требований бэклога.
- **Дизайнер**: заблокированные «на дизайне» и интерфейсные задачи (фронт, бэк+фронт) бэклога и очереди без описания дизайна и без макетов.
- **Дизайн на согласовании (владелец)**: задачи с описанием дизайна, макетом или файлами без утверждения — вкладка «Дизайн». Утверждение кладёт дизайн в Библиотеку (`design-<ключ>`, вид «спецификация»); возврат блокирует задачу на дизайне. Задача с флагом «нужен макет» не уходит в «В очереди» без утверждения.
- **Разработчики**: «В очереди» с кодом (`layer` ≠ none), без открытых зависимостей, без пересечения по файлам с чужой работой, без открытых вопросов.
- **Не-код: исследования и инструкции**: «В очереди» без кода (`layer` = none).
- **Тестировщик**: «На проверке» с кодом, у которых текущий коммит ветки не проверен, никто не держит аренду и нет паузы после запуска без вердикта.
- **Деплоер**: «На проверке» с отметкой тестировщика ровно на текущем коммите ветки, в окне выкладки, по одной.
- **Согласования (владелец)**: «На проверке» без кода.
- **Нужен ты (владелец)**: заблокированные на владельце и продукте, брошенные, затянувшаяся проверка, упавшие запуски.

Ветка задачи с кодом — всегда `task/<КЛЮЧ>`; если поле ветки пустое, так и считается.

**Каждая задача привязана к исполнителю** по слою и статусу (`executorOf` в `src/lib/workers.ts`), чип в бэклоге показывает его: сейчас — кто делает следующий шаг (триаж, продакт, дизайнер, тестировщик, деплоер), в итоге — разработчики (код) или не-код (без кода). Задачи без исполнителя не бывает; если чип не тот — неверный слой или статус.

## 3. Правила переходов, которые легко нарушить

1. **Разблокировка возвращает задачу туда, откуда её заблокировали.** С проверки — на проверку (ветка цела, тестировщик проверит заново), из бэклога — в бэклог на новый разбор, из работы и очереди — в очередь. Явно выбрать другой статус может владелец или техдиректор через `--force`.
2. **В очередь — только через готовность**: критерии проверяемы, зависимости закрыты, есть область файлов. Сторож обходит это только для брошенных задач.
3. **Проверка привязана к коммиту.** Новый коммит в ветке — новая проверка. Возврат на доработку обнуляет отметку тестировщика.
4. **Запуск тестировщика без вердикта не засчитывается**: час паузы, после второго — блокировка на техдиректоре.
5. **Из «В работе» задачу сдаёт, передаёт или блокирует только тот, кто её держит.**
6. **Триаж отменяет только `IN-N`** и только после переноса в настоящие задачи.
7. **Воркеры не выкладывают руками**: только `scripts/deploy-task.sh`, только протестированный коммит, при провале — откат.

## 4. Сторож и диспетчер

- **Сторож** (`/api/cron`, каждые 15 минут): отмечает брошенные задачи без пульса, через 4 часа возвращает их в очередь с сохранённой веткой; снимает блокировку `deps`, когда зависимости закрылись; напоминает о задачах «В работе» без исполнителя и о проверке дольше суток. Ничего не удаляет.
- **Диспетчер** (таймер systemd, раз в минуту): считает свободные слоты пулов, дневные лимиты, окно выкладки и запускает воркеров. Пул с исчерпанным лимитом стоит до полуночи по Еревану — это видно на вкладке «Воркеры». Лимит триажа по умолчанию 40 запусков в сутки: каждая `IN-N` — отдельный запуск.

## 5. Инварианты доски

Проверяются на странице «Здоровье» → «Проверка доски» и командой `node scripts/cc-audit.mjs`. Нарушение — повод для действия человека, а не для ожидания:

| Проверка | Что делать |
|---|---|
| заблокирована без причины или без `blockedOn` | дописать причину и кто снимает |
| человек ответил после блокировки — ждёт триажа | ничего: триаж подхватит на ближайшем запуске; если стоит больше часа — смотреть лимит триажа |
| заблокирована на зависимостях, а они закрыты | сторож снимет сам; иначе `unblock` |
| в бэклоге без разбора | очередь триажа; если не убывает — лимит или пауза воркеров |
| в очереди или на проверке с открытыми зависимостями | вернуть в бэклог или закрыть зависимость |
| на проверке без ветки в репозитории | `git push -u origin task/<КЛЮЧ>` или вернуть разработчику |
| входящая `IN-N` открыта и не заблокирована | триаж должен перенести в настоящие задачи и отменить |
| зависимость на несуществующую задачу | поправить `depends` |
| в работе без исполнителя или без пульса больше часа | сторож вернёт в очередь; можно `handoff` |

## 6. Как не потерять задачу

- Любая просьба о работе — карточка: `IN-N` через Intake, бота команды или `node scripts/cc.mjs intake`. Чат не исполняет просьбы мимо доски.
- Каждая карточка проходит триаж; каждая сдача — тестировщика и деплоера; каждый вопрос — в ленте задачи, а не в переписке.
- Ответ владельца пишется в ленту заблокированной задачи (вкладка «Нужен ты») — тогда триаж её увидит.
- Раз в день — `node scripts/cc-audit.mjs` или страница «Здоровье».
